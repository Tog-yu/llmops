# LLMOps API 本地启动指南

本文说明在本机运行 **imooc-llmops-api** 前需要准备的环境、配置与命令顺序，便于排查「依赖装不上 / 连不上库 / 迁移版本不对」等问题。

---

## 1. 项目是什么

- **技术栈**：Python + **Flask** + SQLAlchemy + **PostgreSQL** + **Redis** + **Celery**（异步任务）+ Weaviate（向量库，部分能力依赖）等。
- **HTTP 入口**：`app/http/app.py` 中的 `app` 实例；默认 `python app/http/app.py` 会在 **debug** 下监听（Flask 默认一般为 `http://127.0.0.1:5000`）。
- **环境变量**：通过项目根目录的 `.env` 加载（见 `python-dotenv`），模板为 `.env.example`。

### 1.1 不纳入 Git 的运行时数据

以下路径由程序在运行时生成或下载，**已在 `.gitignore` 中排除**，克隆仓库后需自行产生（首次跑相关功能时会自动拉取或写入）：

- `internal/core/embeddings/models--*/`：Hugging Face Hub 本地模型缓存（体积大）。
- `internal/core/vector_store/*.faiss`、`*.pkl`：FAISS 向量索引文件。

目录本身通过 `internal/core/embeddings/.gitkeep`、`internal/core/vector_store/.gitkeep` 占位保留在仓库中。

## 2. 必须先搞定的环境

按优先级说明：**缺了前几项，服务无法正常启动**。

### 2.1 Python 版本

- **建议使用 Python 3.10 / 3.11**（与当前 `requirements` 中大量二进制包、torch 等更匹配）。
- **不推荐**用过新的 Python（例如 3.14）直接装全量依赖，容易出现无 wheel、解析失败等问题。

### 2.2 PostgreSQL（必需）

- 配置项：`SQLALCHEMY_DATABASE_URI`（见 `.env.example`）。
- 需要**预先创建数据库**（例如库名 `llmops`），且账号对库有建表权限。
- 首次启动或换机器后需执行 **数据库迁移**（见下文「迁移」）。

### 2.3 Redis（必需）

- 配置项：`REDIS_HOST`、`REDIS_PORT` 等；Celery 的 broker/result 默认也指向同一 Redis 上的不同 **DB 编号**（`CELERY_BROKER_DB`、`CELERY_RESULT_BACKEND_DB`）。
- 本机开发请保证 Redis 进程已启动且端口可连。

### 2.4 环境变量文件 `.env`（必需）

- 复制模板：`cp .env.example .env`，再按本机修改。
- **至少**保证：
  - `SQLALCHEMY_DATABASE_URI` 指向你的 Postgres；
  - `REDIS_HOST` / `REDIS_PORT` 正确；
  - **`JWT_SECRET_KEY` 为非空**（登录签发 token 用）；
  - **`OPENAI_API_KEY` 为非空字符串**（启动时会初始化 OpenAI Embeddings；本地可填占位，但真实向量化/调用模型需有效 Key）。

### 2.5 Weaviate（强烈建议；无则部分能力降级）

- 配置：`WEAVIATE_HOST`、`WEAVIATE_PORT`（常见为 HTTP `8080`）。
- 用于知识库向量检索、索引等与 Weaviate 相关的功能。
- 若本机**未**启动 Weaviate：当前代码会对连接失败做容错，**HTTP 服务仍可启动**，但依赖向量库/集合的接口在运行时会不可用或报错，需自行启动 Weaviate（例如 Docker）后再测全量功能。

### 2.6 Celery Worker（按需）

- 涉及**异步任务**的功能（如文档构建、部分后台任务）需要单独启动 Worker，否则任务会一直积压在 Redis。
- 典型命令见下文「启动 Celery」。

### 2.7 其他依赖服务（按业务使用）

- **各 LLM / 工具 Key**：OpenAI、通义、月之暗面、千帆、Serper、高德、GitHub OAuth、腾讯云 COS 等，见 `.env.example`；不用对应功能时可留空，但可能影响相关接口。
- **LangSmith**：可选，用于链路追踪。

### 2.8 系统与补充 Python 包（常见问题）

- **macOS**：原 `requirements.txt` 中含 **Windows 专用包**（如 `pywin32`）及 **Intel MKL 相关包**，在 Apple Silicon 上通常无法安装；需使用裁剪/替代清单或逐包处理（见下一节）。
- **FAISS**：若启动报缺少 `faiss`，需安装 **`faiss-cpu`**（或按报错提示的 GPU 版本）。
- **Flask-Login**：若报 `No module named 'flask_login'`，需安装 **`Flask-Login`**（与课程仓库版本可能未写入 lock 有关）。
- **libmagic**（文件类型识别）：`python-magic` 在 macOS 上常需本机安装 `libmagic`（如 Homebrew `file-formula` / `libmagic`），按报错处理即可。

## 3. 安装依赖

### 3.1 仓库内 `requirements.txt` 编码说明

- 根目录 `requirements.txt` 为 **UTF-16 LE** 编码。若用 shell 管道过滤，请先 **`iconv` 转成 UTF-8**，否则 `grep` 可能误判为二进制文件。

### 3.2 Windows

- 在对应 Python 环境下：`pip install -r requirements.txt`（若个别包失败，按报错微调版本）。

### 3.3 macOS（尤其 Apple Silicon）推荐做法

1. 从 UTF-16 的 `requirements.txt` 生成 **UTF-8** 的本地清单（示例逻辑）：
   - 去掉无法在 Mac 安装的包：`pywin32`、`python-magic-bin`、`intel-openmp`、`mkl`、`tbb`；
   - 将 **`validators` 调整为与 `weaviate-client` 兼容的版本**（例如 `0.34.0`，避免与 `weaviate-client==4.8.1` 冲突）；
   - 若出现 **`urllib3` 与 `tcvectordb` 冲突**：`tcvectordb` 在本仓库业务代码中**未直接引用**，本地可暂时从清单中移除再安装（若你确实需要腾讯云向量库再单独接入）。
2. 安装：`pip install -r <你的_utf8_清单.txt>`。
3. 再执行补充安装（若未进清单）：
   - `pip install Flask-Login`
   - `pip install faiss-cpu`

> 仓库中若已有维护好的 `requirements-mac.txt`，可直接以该文件为准安装，并留意其注释或生成方式是否与你的环境一致。

## 4. 数据库迁移

在项目根目录、已激活虚拟环境且已配置 `.env` 的前提下：

```bash
export FLASK_APP=app.http.app:app
flask db upgrade
```

### 4.1 Alembic 版本与仓库不一致

若报错类似 **`Can't locate revision identified by 'xxxx'`**，说明当前 Postgres 里 **`alembic_version` 表记录的版本号**与本仓库 `internal/migration/versions` 不匹配（常见于用「旧库」连「新代码」）。

**本地开发**可任选其一：

- **重建空库**（会清空数据）：`dropdb` / `createdb` 后重新 `flask db upgrade`；或
- 在明确后果后使用 `flask db stamp` 等命令对齐版本（需懂 Alembic，慎用）。

## 5. 启动服务

### 5.1 启动 HTTP API

在项目根目录：

```bash
# 已创建 .venv 并安装依赖
source .venv/bin/activate   # Windows: .venv\Scripts\activate
python app/http/app.py
```

或使用 Flask CLI（需 `FLASK_APP`）：

```bash
export FLASK_APP=app.http.app:app
flask run
```

### 5.2 启动 Celery Worker（异步任务）

另开终端，同样在项目根目录、同一虚拟环境与 `.env`：

```bash
export FLASK_APP=app.http.app:app
celery -A app.http.app.celery worker -l info
```

说明：`-A` 指向的 `celery` 对象定义在 `app/http/app.py` 中（`celery = app.extensions["celery"]`）。业务里通过 `shared_task` 注册的任务会在导入相关模块时注册；若 Worker 未加载到任务模块，可根据报错补充 `include` 或保证从 `app.http.app` 导入链能加载到 `internal.task.*`。

## 6. 启动前自检清单（建议按顺序勾）

| 顺序 | 检查项 |
|------|--------|
| 1 | Python 版本 3.10/3.11，虚拟环境已激活 |
| 2 | Postgres 已启动，数据库已创建，`SQLALCHEMY_DATABASE_URI` 正确 |
| 3 | Redis 已启动，`REDIS_HOST`/`PORT` 正确 |
| 4 | 根目录存在 `.env`，`JWT_SECRET_KEY`、`OPENAI_API_KEY` 已填（后者可用占位） |
| 5 | 依赖已安装（Mac 注意裁剪清单 + `Flask-Login` + `faiss-cpu`） |
| 6 | 已执行 `flask db upgrade` 且无 revision 冲突 |
| 7 | （可选）Weaviate 已启动 → 向量相关功能可测 |
| 8 | （按需）Celery Worker 已启动 → 异步任务可执行 |

## 7. 常见问题速查

| 现象 | 可能原因 | 处理方向 |
|------|----------|----------|
| `Can't locate revision ...` | 数据库 Alembic 版本与代码不一致 | 重建库或 `stamp`/对齐迁移 |
| `Connection to Weaviate failed` | 8080 无服务 | 启动 Weaviate；或先忽略向量接口 |
| `No module named 'faiss'` | 未装 faiss | `pip install faiss-cpu` |
| `No module named 'flask_login'` | 缺 Flask-Login | `pip install Flask-Login` |
| `openai_api_key` 校验失败 | `OPENAI_API_KEY` 为空 | `.env` 填占位或真实 Key |
| pip 冲突 `validators` / `weaviate-client` | 版本钉死冲突 | 提升 `validators` 或降低 weaviate-client（需整体兼容） |
| pip 冲突 `urllib3` / `tcvectordb` | tcvectordb 上限锁 urllib3 | Mac 本地清单移除 tcvectordb 或单独环境 |
| Intel `mkl` / `intel-openmp` 装不上 | ARM Mac 不支持 | 从本地清单移除，用 torch 官方 Mac ARM wheel |
