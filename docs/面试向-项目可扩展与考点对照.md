# LLMOps API：可扩展方向与面试考点对照

本文档说明本仓库**已有能力**与**可扩展点**，并尽量与常见大模型 / RAG / Agent / 工程面试题对齐，便于写简历、准备口述与动手 demo。

## 2. RAG 全链路（考点：RAG 流程、向量怎么存、BM25、RRF、精排、幻觉）

### 2.1 现状

- **写入**：上传文件 → 解析 → 分段 → 写入向量库与关键词表（见索引相关 service）。
- **召回**：语义（稠密）+ 全文（Jieba 关键词命中频次排序），混合时为 **0.5 / 0.5 的 Ensemble**，不是 BM25，也不是 RRF。
- **无**独立的 cross-encoder / 重排序步骤。

### 2.2 可扩展（紧扣面试）

1. **BM25**  
   - **考点**：BM25 公式、与 TF-IDF 区别、稀疏检索。  
   - **做法**：对 `Segment` 正文建倒排，用 `rank-bm25`（已在 `requirements.txt`）或 Elasticsearch/OpenSearch 的 BM25；与现有向量路并行。  
   - **挂钩代码**：替换或并行于 `FullTextRetriever` 的打分逻辑。

2. **RRF（Reciprocal Rank Fusion）**  
   - **考点**：RRF 公式、为何比简单加权稳健、多路异构排序融合。  
   - **做法**：向量路、BM25 路各取 Top-K，按 \( \mathrm{RRF}(d)=\sum_r \frac{1}{k+\mathrm{rank}_r(d)} \) 融合（\(k\) 常取 60），再截断送入 LLM。  
   - **挂钩代码**：在 `RetrievalService.search_in_datasets` 混合分支中，用 RRF 替代或补充 `EnsembleRetriever`。

3. **Cross-encoder 二次精排**  
   - **考点**：双塔 vs 交叉编码、延迟与效果权衡、为何不能「只上精排」（全库代价、延迟、域外片段）。  
   - **做法**：RRF 合并后取 Top-20～50，用 cross-encoder（如 `cross-encoder/ms-marco-*` 或云 rerank API）重排，再取 Top-3～8 拼上下文。  
   - **挂钩代码**：在检索返回 `LCDocument` 列表之后、拼 prompt 之前插入 `rerank` 层。

4. **片段数量与阈值**  
   - **考点**：召回多少、上下文窗口、噪声与幻觉。  
   - **做法**：配置化 `k`、精排后 `top_n`、相似度阈值；对命中质量打日志做 A/B。  
   - **挂钩代码**：`RetrievalStrategy`、`search_kwargs` 与 App 配置中的 `retrieval_config`。

5. **幻觉**  
   - **考点**：幻觉来源、RAG 如何缓解、仍可能胡编怎么办。  
   - **做法**：强制「仅依据检索片段」的 prompt、引用片段 id、低置信度拒答、多跳检索验证（可新增节点）。  
   - **挂钩代码**：工作流 `LLMNode` 与对话 `conversation_service` 的 system 模板。

6. **知识库中的表格与图片**  
   - **考点**：非纯文本怎么处理。  
   - **做法**：表格 → Markdown/HTML/SQLite 行文本再分段；图片 → caption（多模态模型）+ 向量；复杂 PDF 用版面分析后再切块。  
   - **挂钩代码**：`FileExtractor` 的 loader 选择与后续分段策略。

## 3. LangChain / NL2SQL（考点：自然语言转 SQL 步骤、上千张表 schema、增删改审核）

### 3.1 现状

- 广泛使用 LangChain / LangGraph，但**无 Text-to-SQL 专用链**；SQLAlchemy 用于业务库 ORM，不是 NL2SQL。

### 3.2 可扩展

1. **NL2SQL 典型步骤（面试标准答法 + 落地）**  
   - Schema 筛选（只选相关表/列）→ 方言与约束说明 → 生成 SQL → 语法与安全校验 → 仅 SELECT 自动执行 / 写操作走审批。  
   - **挂钩**：新增 `internal/core/tools/nl2sql/` 或 API Tool，由 Agent 调用；表筛选可用 embedding 对「表说明文档」做检索。

2. **上千张表装不进 prompt**  
   - **考点**：元数据检索、数据字典向量化、粗排表名再细排列。  
   - **做法**：与 RAG 同构——「表/列说明」进向量库；问句先召回 Top-N 张表，再把仅这些表的 DDL 塞进 prompt。

3. **增删改人工审核**  
   - **考点**：前后端协作、审计、权限。  
   - **做法**：生成 SQL 后写入 `pending_sql` 表 → 管理端列表展示 → 审批人执行或驳回 → 记录 `account_id`、时间、影响行数；与现有 `Account`、JWT 体系一致。

## 4. Agent、工具与 MCP（考点：Agent 组成、MCP 调工具）

### 4.1 现状

- LLM + Tools：`app_config_service` 将配置转为 LangChain `BaseTool`；内置工具、API Tool、工作流工具；`FunctionCallAgent` / `ReactAgent`。

### 4.2 可扩展

1. **MCP（Model Context Protocol）**  
   - **考点**：通过 MCP 暴露工具给 IDE/Agent。  
   - **做法**：将「知识库检索」「执行已批准 SQL」等封装为 MCP Server，与 Cursor/Claude Desktop 对接；业务上仍调用现有 HTTP 或 Python service。

2. **多智能体 / 路由（类比 Dify）**  
   - **考点**：多领域、编排与路由。  
   - **做法**：上层 Router LLM 或规则选「子 Agent / 子工作流」；本项目已有 **Workflow 转 Tool**，可扩展「路由节点」或独立路由应用配置。

## 5. 模型与训练向（考点：BERT 预训练、Transformer 编解码、LoRA、PEFT、范式）

### 5.1 现状

- 本仓库为 **推理与 LLMOps API**，不包含训练代码；Embedding 默认 `OpenAIEmbeddings`（见 `embeddings_service.py`），可切换为本地模型。

### 5.2 可扩展（偏「架构叙事」而非本仓必做）

1. **本地 Embedding / 微调向量模型**  
   - 与面试「词向量怎么训」：可答理论 + 说明线上用开源句向量 + 领域语料 contrastive 或双塔微调；工程上替换 `Embeddings` 实现即可。

2. **LoRA / PEFT**  
   - **考点**：只训少量参数、灾难性遗忘、与全参对比。  
   - **做法**：不在本 API 内训；可描述「底座模型 + LoRA 适配器服务」与本 API 通过统一模型网关对接。

3. **范式**  
   - Prompting、RAG、Fine-tuning、Tool use — 本项目已覆盖 RAG + Tool；可在文档/答辩中画一张「能力矩阵」。

## 6. NLP 与业务算法（考点：层级分类误差传播、高频问、相似问、问题改写）

### 6.1 现状

- 无层级分类器实现；对话与消息有存储，未内置「FAQ 挖掘 / 相似问 / 改写」模块。

### 6.2 可扩展

1. **层级分类第一类错导致全错**  
   - **考点**：校准、多标签、级联纠错、用检索替代硬分类。  
   - **做法**：用「检索 Top 意图 + 置信度阈值」替代单一根节点；或二级用独立纠错模型；可与工作流条件分支结合。

2. **历史问答对中高频问题提取**  
   - **做法**：对 `Message.query` 归一化 + 聚类 / SimHash + 频次统计；或向量聚类中心代表问题。

3. **相似问题检索**  
   - **做法**：对问句做 embedding 存向量库，近邻搜索；可与 BM25 混合 + RRF。

4. **问题改写（Query Rewriting）**  
   - **做法**：在 `RetrievalService` 前增加一步 LLM 或多查询扩展（HyDE、step-back 等），写入工作流或中间件。

## 7. 工程与部署（考点：慢响应优化、单卡消费级 GPU、知识图谱）

### 7.1 已有可讲点

- Redis 缓存 Embedding；Celery 异步索引；FAISS 本地加载；检索 `k` / MMR `fetch_k` 调参。

### 7.2 可扩展

1. **端到端延迟**  
   - 流式输出、检索并行、精排批处理、小模型路由（简单问不走大模型）、连接池与超时。

2. **单卡 RAG 部署**  
   - 小尺寸 Embedding + 量化 LLM（Ollama 等，项目已有 Ollama provider 线索）+ CPU 向量库或轻量 FAISS；重排可选更小 cross-encoder 或省略。

3. **知识图谱**  
   - **考点**：图谱与向量互补。  
   - **做法**：实体关系抽取后写入图数据库，检索时「子图摘要 + 向量片段」一并给 LLM；与本项目 Dataset/Segment 可并行存在。

## 9. 实施优先级建议（做 demo 时）

1. **检索增强**：BM25 或 ES + RRF +（可选）cross-encoder — 与 RAG 面试重合度最高。  
2. **Query 改写**：改动面小，易演示召回提升。  
3. **NL2SQL + 审核**：与「SQL 助手」简历强绑定。  
4. **MCP**：展示工程化与生态对接。
